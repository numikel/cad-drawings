# AGENTS.md — working on the cad-drawings repo

This repository will be published (MIT). Everything committed here must be safe for strangers to read and useful to them.

## Publication profile (hard rules)

1. **Generic.** The skill improves how an agent handles CAD drawings. It does not teach any client's data, layer names, block names, sheet layouts or conventions. Project specifics belong in the user's own `CAD_CONVENTIONS.md`.
2. **Cross-platform.** Windows, macOS and Linux work without paid software (ezdxf + a DWG converter). COM automation of AutoCAD or a compatible CAD is an optional, Windows-only backend.
3. **Checks its environment.** `scripts/doctor.py` (stdlib only) reports what is missing and proposes install commands. Nothing installs anything without the user's consent.
4. **Agent-neutral text.** `SKILL.md` and `references/` never name a host's tools (no `Read`, `Bash`, `Task`, `AskUserQuestion`). Use semantic names: "shell", "interactive question tool", "image-viewing capability". Format follows https://agentskills.io/specification.
5. **Asks the user** through the host's interactive question tool when available, otherwise as a plain question, then waits. Scripts never prompt.
6. **English** for all skill content, docs and code comments. (Conversation with the maintainer is in Polish.)
7. **Licenses.** Required dependencies are permissive: ezdxf (MIT), pypdfium2 (Apache-2.0/BSD-3), pywin32 (PSF). PyMuPDF (AGPL) only as an optional, lazily imported accelerator. ODA File Converter, LibreDWG and Poppler are external programs: never bundled, never mirrored.

## Forbidden in the repo

- Vendor files: `.pc3 .pmp .ctb .stb .shx .lin .pat .dwt .tlb`, sample DWG/DXF from a CAD installation, help or ActiveX reference excerpts, `gen_py` output.
- Binaries of ODA, Poppler, MiKTeX, LibreDWG, PyMuPDF/MuPDF.
- Client drawings, their renders, user paths (`C:\Users\...`), client or project names, Polish project jargon.
- Fixtures other than those generated by `skills/cad-drawings/evals/make_fixtures.py` (synthetic only).
- Anything under `_local/` (git-ignored working material: plan, old-skill snapshot, baseline transcripts).

CI greps for forbidden strings and fails the build on a hit; run `python skills/cad-drawings/tests/check_forbidden.py` locally before every commit.

## Engineering rules

- **No skill edit without a failing test first** (superpowers:writing-skills). Order: baseline RED on synthetic fixtures with the old skill → implement → GREEN → close loopholes.
- **Mechanical rules go in code, judgement goes in SKILL.md.** One COM client per CAD instance (lock file with PID), restore system variables, fresh run directories, never trust an artifact older than its source, cleanup file-by-file (never `rm -rf`), meaningful exit codes.
- **Script output contract:** short JSON on stdout (< ~4 KB), details in files, diagnostics on stderr, exit codes 0 ok / 1 error / 2 bad args / 3 missing dependency / 4 resource busy / 5 timeout / 6 precondition failed / 7 partial. No interactive prompts; `--dry-run` and explicit `--overwrite`; UTF-8 forced internally.
- **Never name a module after the standard library** (`inspect.py` once broke `import ezdxf`).
- **COM tests run serially, one instance, synthetic fixtures only**, marked `@pytest.mark.com`, and only after the maintainer confirms no CAD work is in progress.
- Dev environment: `.venv` (Python 3.13, ezdxf>=1.4.4, pywin32>=312). On Windows `uv run` can fail from some shells; call `.venv/Scripts/python.exe -m <tool>` instead.

## Parallel agents

Each track writes only to its own files and its own scratch subdirectory. Shared contracts (JSON output schema, `edit-spec.schema.json`, `cadlib` API) are written first by the main context. Agents delete large intermediate artifacts (DXF/DWG copies, renders) from scratch before reporting.
